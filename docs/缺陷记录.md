# 缺陷记录

开发与自测阶段发现的问题及修复方式。复现和验证需在 Windows 下编译运行（见 README）。

## BUG-001 敌机只有最上面一行参与碰撞判定

- **严重程度**：高
- **现象**：子弹从敌机中下部穿过时不消失、不计分；战机与敌机下半部分重叠也不会坠毁，出现穿模。
- **原因**：`judgeCoordInFrame()` 的 Y 轴上界误写成 `frame.position[0].Y`（矩形左上角），正确应为 `frame.position[1].Y`（右下角）。由于下界同样使用 `position[0].Y`，实际条件退化为“点必须正好位于敌机顶行”。
- **修复**：上界改为 `frame.position[1].Y`，使矩形包含判定完整覆盖敌机 4×3 的区域。
- **验证**：瞄准敌机第二、三行射击应正常命中；战机从敌机下方穿过应判定坠毁。

## BUG-002 分数跳过阈值后等级永久不再提升

- **严重程度**：中
- **现象**：同一帧内多枚子弹命中不同敌机时，分数可能从 115 直接跳到 125，等级没有提升；之后即使达到 360 / 480 分也不再升级。
- **原因**：`printScore()` 用 `score == 120 / 360 / 480` 精确相等判断，且升级标志 `flag_rank` 要求按顺序推进。一旦跳过某个阈值，该分支永远不成立，后续分支又因 `flag_rank` 不匹配无法触发。
- **修复**：阈值判断改为 `score >= 120 / 360 / 480`，标志位仍按顺序补触发，等级逐级提升。
- **验证**：让同一帧击毁多架敌机、分数跨过 120，下一帧等级应正常下降。

## BUG-003 随机数取模使用负除数

- **严重程度**：低（潜在）
- **现象**：`random(a, b)` 采用 `rand() % (a-b) + a`，在 `a < b` 时除数为负。当前编译器（C++11 及以后，余数符号随被除数）下结果范围恰好正确，但换编译器 / 语言标准可能产生屏幕外坐标；`a == b` 时还会除零。
- **修复**：改为 `rand() % (b-a) + a`，并增加 `b <= a` 时直接返回 `a` 的保护。
- **验证**：连续生成敌机坐标，应始终落在 `[a, b)` 内。

## 附：源码编码调整

原始源码为 GBK 编码。为便于在 GitHub / VS Code 中阅读，已转为 UTF-8，并在程序中做两处配套调整，保证运行时的中文显示正常：

- `main()` 中调用 `SetConsoleOutputCP(CP_UTF8)`；
- MSVC 下通过 `#pragma execution_character_set("utf-8")` 将字符串字面量按 UTF-8 编码。
